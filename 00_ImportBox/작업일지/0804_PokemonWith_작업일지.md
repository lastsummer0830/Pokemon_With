## 4. 실행프로그램 아이콘 교체 (세션 중 요청)

`01_Resources/Title/Logo/Program_Logo_Transparent.png` → 파스텔 크리스탈 몬스터볼.

| 파일 | 한 일 |
|---|---|
| **`tools/make-icons.py` (신규)** | 로고 PNG 한 장 → `electron/assets/icon.ico`(16~256px 7종) + `icon.png`(창) + `public/favicon.png`(탭) |
| **`tools/set-exe-icon.sh` (신규)** | **exe 파일 자체**의 아이콘 교체 |
| `package.json` | `build.win.icon` 추가 |
| `electron/main.cjs` | BrowserWindow `icon` |
| `index.html` | 탭 favicon |

### ⚠️ 왜 스크립트가 따로 필요한가 (다음 세션이 헤매지 않게)

`package.json`의 **`win.signAndEditExecutable: false`** 때문에 electron-builder가 exe를 아예 손대지 않는다
(WSL 리눅스에선 exe를 편집하는 rcedit이 wine 없이는 못 돈다). 그래서 **윈도우쪽 rcedit을 WSL interop으로 직접** 부른다.

- **`app:bake`(dist만 교체)는 exe를 안 건드리므로 아이콘이 그대로 남는다** → 다시 안 돌려도 된다.
- `npx electron-builder --win --x64`로 exe를 새로 구우면 초기화된다 → 그때 `bash tools/set-exe-icon.sh` 한 번.
- 아이콘 원본은 **`electron/assets/`**에 둔다. `build/`는 `.gitignore(**/build/)` 대상이라 거기 두면 **다른 PC로 안 넘어간다.**
- 적용 확인은 exe에서 **아이콘을 다시 꺼내** 봤다(PowerShell `ExtractAssociatedIcon`) — 눈대중 아님.
- 윈도우 탐색기가 옛 아이콘을 캐시해 안 바뀐 것처럼 보일 수 있다.

## 6. 이번에 걸린 함정

1. ⭐ **검증 스크립트가 플레이어를 벽·가구 위로 순간이동시키고 있었다.** 말은 걸려서 통과했는데
   **사진에 주인공이 침대에 올라선 채** 찍혔고, 볼이 주인공에 가려 안 보였다.
   → `faceTile()`이 **설 자리의 `walkable()`을 먼저 확인**하게 고쳤다. "말이 걸린다 ≠ 갈 수 있다"를 구분할 것.
2. **볼이 놓인 칸(5,6)은 원본 타일부터 막힘**이다(침대 옆). "주우면 지나갈 수 있다"로 확인하면 틀린다 → 격자 값과 대조할 것.
3. **민가는 방이 PNG (96,32)에서 시작한다**(센터·마트는 (0,0)). `content`를 `[너비,높이]`에서 **`[x,y,너비,높이]` 사각형**으로 바꿨다 — 안 그러면 방이 화면 구석으로 쏠린다.
4. 0803 함정 그대로 재확인: **public/에 새 파일 만들면 dev 서버 재시작**(이번에도 필요했다 — png/json/ogg 전부 `content_type` 확인함).
5. `DebugMenuScene` 바로가기는 **목록 순서대로 단축키가 배정**된다 → 중간에 끼워 넣으면 기존 키가 밀린다. 새 항목은 **끝에** 붙이고 `keyNames`를 늘렸다.
