## 4. 실행프로그램 아이콘 교체 (세션 중 요청)

`01_Resources/Title/Logo/Program_Logo_Transparent.png` → 파스텔 크리스탈 몬스터볼.

| 파일 | 한 일 |
|---|---|
| **`tools/make-icons.py` (신규)** | 로고 PNG 한 장 → `electron/assets/icon.ico`(16~256px 7종) + `icon.png`(창) + `public/favicon.png`(탭) |
| **`tools/set-exe-icon.sh` (신규)** | **exe 파일 자체**의 아이콘 교체 |
| `package.json` | `build.win.icon` 추가 |
| `electron/main.cjs` | BrowserWindow `icon` |
| `index.html` | 탭 favicon |

### ⚠️ 왜 스크립트가 따로 필요한가 (다음 세션이 헤매지 않게)

`package.json`의 **`win.signAndEditExecutable: false`** 때문에 electron-builder가 exe를 아예 손대지 않는다
(WSL 리눅스에선 exe를 편집하는 rcedit이 wine 없이는 못 돈다). 그래서 **윈도우쪽 rcedit을 WSL interop으로 직접** 부른다.

- **`app:bake`(dist만 교체)는 exe를 안 건드리므로 아이콘이 그대로 남는다** → 다시 안 돌려도 된다.
- `npx electron-builder --win --x64`로 exe를 새로 구우면 초기화된다 → 그때 `bash tools/set-exe-icon.sh` 한 번.
- 아이콘 원본은 **`electron/assets/`**에 둔다. `build/`는 `.gitignore(**/build/)` 대상이라 거기 두면 **다른 PC로 안 넘어간다.**
- 적용 확인은 exe에서 **아이콘을 다시 꺼내** 봤다(PowerShell `ExtractAssociatedIcon`) — 눈대중 아님.
- `npm run app:bake`로 **오늘 작업까지 exe에 구웠다**(굽기는 exe를 안 건드리므로 아이콘 그대로 유지됨을 확인).
- 윈도우 탐색기가 옛 아이콘을 캐시해 **안 바뀐 것처럼 보인다**(실제로 겪음 — exe는 이미 정상인데 바탕화면만 옛 그림).
  해결: `ie4uinit.exe -show` + **바로가기(`PokemonWith.lnk`)의 `IconLocation`을 exe 대신 `electron/assets/icon.ico`로 바꿔 저장**
  (다른 파일이라 캐시를 우회한다). 이걸로 즉시 바뀌었다.
  ⚠️ 그래서 이 PC의 lnk는 **ico 파일 경로를 직접** 본다 → **리포 폴더명·위치를 바꾸면 아이콘이 깨진다**(lnk 재생성할 것).
  그래도 안 되면 마지막 수단 = `iconcache_*.db` 삭제 + explorer 재시작(열린 탐색기 창이 다 닫힌다).

## 4.5 ⭐⭐ 전수 대조를 **도구로** 바꿨다 (사용자 지적 — 이게 오늘 제일 중요)

> 사용자: *"너 원본 코드랑 그래픽 소스들 보면서 놓친거 뭔지 하나 하나 확인하고 있음? 존나 부족해보이는데"*
> *"하나가 아니라 전체적으로 문제라니까. 뭔 내가 틀린 그림 찾기하는 것도 아니고"*

**맞는 지적이다.** 그때까지는 **작업하는 그 맵만** 훑었다. 그래서 빠진 것을 **사람이 눈으로** 찾아야 했다.
0803의 "말 걸기가 통째로 없었다"도, 오늘 나온 것들도 전부 같은 원인이다 — 대조가 **일회성 수작업**이었다.

### `tools/ar-map/audit-parity.py` (신규) — 이제 기계가 뱉는다

우리가 이식한 **맵 12장 전부**를 돌면서 원본의 이벤트·페이지·명령·속성을 세고 우리 결과물과 맞춘다.

- ⭐ **"지금 실제로 도는 페이지"의 구멍만** 따로 뽑는다. 안 그러면 스토리라 일부러 뺀 것까지 898건이 섞여 못 쓴다.
- 문(장소이동만 하는 이벤트)·트레이너·씬이 직접 구현한 것은 **"다른 방식으로 반영"**으로 분류해 오탐을 없앴다.
- 맵 데이터엔 안 나오는 **엔진 동작**(원본 Ruby 스크립트가 항상 하는 것)은 `ENGINE_NOTES`에 근거와 반영 여부를 적어 둔다.

**돌린 결과 실제 구멍 2개가 나왔고, 둘 다 오늘 메웠다:**

| 구멍 | 원본 근거 | 고친 것 |
|---|---|---|
| **말 걸어도 NPC가 안 돌아봤다** | `Interpreter.rb`: trigger<3이면 `event.lock` → `Game_Character#lock` → `turn_toward_player`. **`@prelock_direction=0`이라 대화가 끝나도 계속 이쪽을 본다** | `mapEvents.faceDirToward` + WorldScene·BuildingScene. `direction_fix`면 예외 |
| **열매나무가 정지 + 새싹 그림이었다** | `step_anime`(제자리 흔들림) + 원본 `dir=8` | `fieldEventRunner.applyEventSprite`. 속도 8fps = 원본 `pattern_update_speed`의 1/4 |

### ⚠️ 열매나무 시트의 함정 (다음에 또 헷갈릴 것)

`berrytree_*.png`는 **세로 4줄이 방향이 아니라 성장 단계**다(새싹→봉오리→꽃→**열매**). 가로 4칸이 흔들림 프레임.
원본이 `direction_fix=True`로 잠가 둔 이유가 이것 — **돌아보게 만들면 성장 단계가 바뀌어 새싹이 된다.**
0803에는 이 `dir`을 안 뽑아서 **두 그루 다 새싹으로 서 있었다**(오늘 `dir` 추출로 같이 고쳐졌다).

### 추출기가 이번에 더 들고 오게 된 것
`step`(step_anime) · `fixed`(direction_fix) — 값을 안 들고 가면 위 두 가지를 **런타임에서 판단할 수 없다.**

### 지금 상태: **⭐ 실제로 영향 있는 구멍 0개**
남은 것은 전부 "알고서 미룬 것"이다 — 반쪽 페이지 28개(스토리 3종·아머까오 등) · 태초마을 EV011(포켓몬 따라다니기) 1개.

## 6. 이번에 걸린 함정

1. ⭐ **검증 스크립트가 플레이어를 벽·가구 위로 순간이동시키고 있었다.** 말은 걸려서 통과했는데
   **사진에 주인공이 침대에 올라선 채** 찍혔고, 볼이 주인공에 가려 안 보였다.
   → `faceTile()`이 **설 자리의 `walkable()`을 먼저 확인**하게 고쳤다. "말이 걸린다 ≠ 갈 수 있다"를 구분할 것.
2. **볼이 놓인 칸(5,6)은 원본 타일부터 막힘**이다(침대 옆). "주우면 지나갈 수 있다"로 확인하면 틀린다 → 격자 값과 대조할 것.
3. **민가는 방이 PNG (96,32)에서 시작한다**(센터·마트는 (0,0)). `content`를 `[너비,높이]`에서 **`[x,y,너비,높이]` 사각형**으로 바꿨다 — 안 그러면 방이 화면 구석으로 쏠린다.
4. 0803 함정 그대로 재확인: **public/에 새 파일 만들면 dev 서버 재시작**(이번에도 필요했다 — png/json/ogg 전부 `content_type` 확인함).
5. `DebugMenuScene` 바로가기는 **목록 순서대로 단축키가 배정**된다 → 중간에 끼워 넣으면 기존 키가 밀린다. 새 항목은 **끝에** 붙이고 `keyNames`를 늘렸다.
