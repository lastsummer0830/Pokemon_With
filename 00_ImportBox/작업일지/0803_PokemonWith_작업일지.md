## 0. ⭐ 오늘 가장 중요 — "우리 게임엔 '말 걸기'가 아예 없었다"

사용자 지시: *"제발 어나더레드 원본 리소스 좀 제대로 보면서 놓친 부분 없는지 생각 좀 하고 작업해라."*

그래서 우리가 이식한 6개 맵(1번도로·태초·상록 + 집1F/방2F/연구소)의 **원본 이벤트 39개를 전부 뽑아** 우리 것과 맞춰봤다.

> **우리 것은 문 6개 + 트레이너 2명뿐이었다. 필드에서 확인키를 눌러도 아무 일도 일어나지 않았다.**

0802의 언덕과 **같은 종류의 구멍**이다 — 그림은 맞는데 동작이 없다.
그래서 2순위였던 물 애니보다 **필드 상호작용을 먼저** 했다(그게 없으면 팻말·NPC·아이템·열매를 하나도 못 붙인다).

**교훈으로 굳힐 것: 새 맵/새 화면을 이식하면 그 맵의 원본 이벤트 목록도 같이 훑는다.**

## 1. 조작키 — 액션(USE/BACK/MENU/BAG/SPEED)으로 통합 + 키 설정 화면

### 원본 실측(추측 아님)
| 근거 | 내용 |
|---|---|
| 게임폴더 `조작키 및 안내사항.txt` | A버튼 `C` · B버튼 `X` · "가방 및 사용" `Z` · 스페셜 `D` · 배속 `Q`(배틀 전용) · F1 커스터마이즈 |
| `mkxp.json` bindingNames + mkxp-z 기본배치 | 물리 C=USE · X=BACK · **Z=ACTION** · D=SPECIAL · Q=L(AUX1) |
| `Scripts.rxdata` → `Scene_Map.rb` | `USE→interact_calling` · **`ACTION→menu_calling`** · `SPECIAL→ready_menu_calling` |

⭐ **원본의 물리 Z는 '가방'이 아니라 '메뉴 열기'다.** 문서의 "가방 및 사용 버튼"이 그 뜻(가방은 그 메뉴 안에 있다).
원본엔 **가방 직행 단축키가 없다** → 우리는 원본 스페셜 자리인 `D`에 뒀다.

### 우리 배치 (사용자 확정: "원본대로 + 되돌리기 프리셋")
- **원본식(기본)**: 확인 `C·Enter·Space` / 취소 `X·ESC` / 메뉴 `Z` / 가방 `D` / 배속 `Q`
- **기존식(프리셋)**: 확인 `Z·Enter·Space·C` / 취소 `X·ESC` / 메뉴 `Enter·X` / 가방 `B` / 배속 `Q`
- Enter·Space는 사용자 지시대로 **계속 확인으로 받는다.**

### 파일
| 파일 | 한 일 |
|---|---|
| **`src/systems/input.ts` (신규)** | 액션 5종·프리셋·localStorage(`myPokemon.keys`)·씬 종료 시 자동 해제·F1 전역 훅 |
| **`src/scenes/KeyConfigScene.ts` (신규)** | 원본 F1 대응. 프리셋 전환 + 액션별 키 다시 잡기 + R 기본값 |
| `src/scenes/OptionsScene.ts` | '키 설정' 줄 추가(그 자리에서 지금 확인키를 보여준다) |
| 18개 파일 약 190곳 | 흩어져 있던 `keydown-ENTER/Z/SPACE/X/ESC`를 전부 액션 API로 이관 |
| `src/scenes/BattleScene.ts` | 배속 Q = **배틀 전용**(time·tween timeScale 2배 + "≫ 배속 2배" 표시, 씬 나갈 때 원복) |

- **원본 배속은 mkxp 엔진의 프레임 스킵**이라 배율을 실측할 수 없다(스크립트에 없음). 우리는 시간 2배로 잡고 근거를 주석에 남겼다.
- **디버그 씬 2개(`DebugMenuScene`·`DebugCheckBarScene`)는 원시 키 유지** — 알파벳 단축키라 액션과 겹친다.
- 겹침 처리: 기존식의 `Enter`는 확인이자 메뉴다 → 실내 상호작용 폴링은 `isActionJustDown(this,"USE",{except:["MENU","BAG"]})`로 메뉴 쪽만 남긴다.

## 4. Y정렬 버그 (사진 보다가 잡음)

바닥 아이템 사진에 볼이 안 보여 파고들었더니, 스프라이트는 제자리인데 **그리는 순서가 원본과 달랐다.**

- 원본(RMXP)은 **y가 큰(아래) 것이 앞에** 그려진다. 우리는 사람·NPC·물건이 전부 `depth 5`라 **나중에 만든 것이 무조건 위**였다.
- → 주인공 위 칸의 몬스터볼이 **주인공 머리를 덮었다**(빨간 모자 위 빨간 볼이라 눈에도 안 띔).
- `yDepth(ty) = 5 + ty*0.001`을 주인공·트레이너·NPC·물건에 넣고, 걸을 때마다(`landOn`) 갱신한다. 전경 레이어는 depth 6이라 안 겹친다.

## 7. ⛔ 가방 색 삽질 — 다음 세션은 이 짓 반복하지 말 것

새 포켓 2칸을 구우면서 **가방 스크롤 화살표가 안 보이는 것**을 건드렸다가 크게 헤맸다. 사용자 격노.

### 내가 한 잘못 (순서대로)
1. 리컬러 규칙이 화살표를 크림으로 덮어 지운 걸 보고 → **화살표를 빨갛게 칠했다.** 트랙까지 빨개져 "필터 씌운 꼴"이 됐다.
2. 원본을 **좁게 잘라만 보고** "슬라이더 띠"가 있다고 착각 → **없는 사각형을 만들어 브라운으로 칠했다.** 화살표 뒤에 색 다른 네모가 생겼다.
3. 그 상태에서 "원본 그대로"를 후보라며 내밀었다. 그건 후보가 아니라 **내가 망가뜨린 걸 되돌린 것**이다.

### 원본 실측 (이제야 제대로 본 것)
- `bg_N.png` = **배경 한 장 전체가 포켓색**(주황·노랑·연두·초록·보라…). **띠 같은 건 없다.**
- 배경에 구워진 화살표 = **빈 트랙**, 푸른회색 `rgb(152,168,184)`.
- `icon_slider.png` = **별도 파일**, 파랑 `rgb(96,136,248)`. 목록이 7줄 넘을 때만 그 위에 그린다(`BagScene.drawSlider`).
- `bag_N.png` = 포켓별 가방 그림 / `bag_N_f.png` = **여주인공용**(원본 `UI_Bag.rb`: `$player.female?`이면 `_f` 우선).

### 최종 상태 = **전부 되돌림**
- `bg_1·2·3·8`·`icon_slider` → **커밋본 그대로**(변경 0). `ui-pastel.py`도 git에서 되돌린 뒤 필요한 것만 재적용.
- 남긴 변경은 두 개뿐: **굽는 목록에 `bg_4`·`bg_5` 추가** + **색상 하한 `0.35→0.45`**(나무열매 배경의 초록 h=0.38이 '아이콘'으로 오인돼 그 칸만 초록이던 것 수정).
- **화살표가 크림 배경에서 잘 안 보이는 문제는 미해결로 남겼다.** 손대려면 먼저 ① 원본 그림 전체를 크게 보고 ② `BagScene`이 언제 무엇을 그리는지 코드로 확인한 뒤 ③ 사용자에게 물어볼 것.

## 8. 함정 (이번에 걸린 것)

1. ⭐ **`public/`에 새 파일을 만들면 dev 서버를 반드시 재시작한다.** 안 하면 vite가 png/json 대신 **index.html을 200으로** 돌려준다(`content_type: text/html`). 이번에 두 번 걸렸다. 그래서 "파일이 404인지"로 존재 판정하면 안 된다.
2. **부팅 직후엔 첫 씬이 `getScenes(true)`에 안 잡힌다**(아직 '시작 중'). 그 상태로 씬을 갈아치우면 **TitleScene이 뒤에 살아남아 D키(디버그) 같은 단축키까지 먹는다.** 검증 스크립트는 `getScenes(true).length > 0`을 기다린 뒤 시작할 것.
3. **같은 그림을 쓰는 이벤트가 여럿이면**(볼 4개·열매나무 2그루) 텍스처를 동시에 만들다 `Texture key already in use`가 난다 → 그림별로 **만드는 작업 하나를 static Map에 기억**해 같이 기다린다.
4. **아이템 사진은 옆에서 찍는다.** 아래에 서면 볼이 주인공 머리에 겹쳐 안 보인다.
5. **잔물결처럼 차이가 작은 애니는 시점 캡처 비교가 무의미하다** → 프레임을 직접 지정해 찍을 것.
6. **원본을 좁게 크롭해서 판단하지 말 것**(§7의 근본 원인). 그림 전체 + 그걸 그리는 코드까지 본 다음에 손댄다.
